## 1. 개요

MarkPad는 Windows 메모장처럼 가볍게 실행되는 `.md` 파일 전용 뷰어·에디터다. 파일을 열면 raw 텍스트가 아니라 **렌더링된 Markdown**이 보이고, 그 렌더링된 화면에서 **바로 편집(WYSIWYG)** 할 수 있다. 상단 툴바의 서식 버튼(제목·굵게·목록·표·코드블록 등)으로 Markdown 문법을 몰라도 GUI 방식으로 신규 문서를 작성하고 편집할 수 있다.

### 1.1 한 줄 정의
"메모장의 가벼움 + Typora의 WYSIWYG 편집 + Word 같은 서식 툴바"를 갖춘 Windows 네이티브 `.md` 편집기.

### 1.2 배경·문제
- Windows 기본 앱(메모장)은 `.md`를 raw 텍스트로만 보여준다. 읽기 불편하고 서식 문법을 직접 타이핑해야 한다.
- VS Code·Obsidian 등은 기능이 과하고 무겁다. "파일 더블클릭 → 바로 읽고 고치기"라는 단순 흐름에 맞지 않는다.
- Typora는 유료·클로즈드이고, 본인 워크플로(AI 도구가 생성한 md 문서 다수, PRD·리서치 노트·투자 리포트 md)에 맞춘 세부 조정이 불가능하다.

### 1.3 목표 (Goals)
| # | 목표 | 성공 기준 |
|---|---|---|
| G1 | `.md` 파일을 열면 렌더링된 상태로 즉시 표시 | 더블클릭 → 렌더 완료까지 1초 이내 (100KB 문서 기준) |
| G2 | 렌더링된 화면에서 직접 편집 (모드 전환 불필요) | 텍스트 입력·서식 적용 시 100ms 이내 반영 |
| G3 | 툴바 버튼만으로 GFM 주요 요소 전부 작성 가능 | 부록 A의 툴바 항목 100% 구현 |
| G4 | 원본 Markdown 손실 없이 저장 (Round-trip 보존) | 편집 안 한 영역은 저장 후 diff 0 |
| G5 | 메모장 수준의 가벼움 | 콜드 스타트 1.5초 이내, 유휴 메모리 150MB 이하 |

### 1.4 비목표 (Non-Goals) — v1에서 제외
- 노트 관리·백링크·태그·그래프 뷰 (Obsidian류 기능)
- 클라우드 동기화, 계정, 협업 편집
- 플러그인 시스템
- 소스(raw) 모드에서의 고급 텍스트 편집 (정규식 치환, 멀티커서 등)
- macOS·Linux 지원, Windows ARM64 빌드
- 상용화·스토어 배포 (개인용)
- `.txt` 파일의 Markdown 렌더링 (`.txt`는 plain 편집만, §3.1 F-FILE-11)

## 2. 사용자 및 시나리오

### 2.1 대상 사용자
- **1차: 본인** — 앱 개발자/PM. AI 도구(Claude, ChatGPT 등)가 생성한 md 문서(PRD, 리서치, 투자 리포트)를 읽고 수정하는 일이 잦음. Markdown 문법에 익숙하지만 매번 타이핑하기보다 툴바로 빠르게 서식을 넣고 싶어 함.
- **2차(참고): 비개발자 가족·동료** — Markdown 문법을 모르지만 md 파일을 열어 읽고 간단히 고쳐야 하는 사람. 툴바 설계 시 이 사용자도 쓸 수 있는 수준을 기준으로 삼는다.

### 2.2 핵심 사용자 시나리오
| ID | 시나리오 | 흐름 |
|---|---|---|
| S1 | AI가 만든 PRD 검토·수정 | 탐색기에서 `prd.md` 더블클릭 → 렌더된 문서 확인 → 표 셀 내용 수정 → 문단 추가 → `Ctrl+S` 저장 |
| S2 | 회의 메모 신규 작성 | 앱 실행 → `Ctrl+N` → 툴바 H1 클릭해 제목 → 체크리스트 버튼으로 할 일 작성 → 스크린샷 `Ctrl+V` 붙여넣기 → 저장 (이미지는 `assets/`에 자동 저장) |
| S3 | 여러 문서 동시 참조 | 탭 3개로 md 파일 열기 → 탭 전환하며 내용 복사·이동 → 최근 파일 목록에서 어제 문서 재오픈 |
| S4 | 공유용 내보내기 | 완성 문서 → 내보내기 → PDF/HTML 생성 → 메신저로 전달 |
| S5 | 코드 스니펫 정리 | 코드블록 버튼 → 언어 선택(kotlin) → 붙여넣기 → 하이라이팅 확인 |

## 3. 기능 요구사항

```
│ 개요   │                                                      │
│ ▸ 1.   │        렌더링된 문서 (WYSIWYG 편집 영역)              │
│ ▸ 2.   │        본문 최대 폭 800px, 가운데 정렬                 │
│   2.1  │                                                      │
│        │                                                      │
├────────┴─────────────────────────────────────────────────────┤
│ 단어 1,234 · 글자 6,789 · UTF-8 · LF · 줄 42       저장됨 ✓  │  ← 상태바
└──────────────────────────────────────────────────────────────┘
```

### 4.2 UX 원칙
- **모드 없음**: 사용자는 "보기"와 "편집"을 구분하지 않는다. 열면 바로 커서를 둘 수 있다.
- **Markdown은 숨기되 배신하지 않는다**: 화면에 `**`·`#` 같은 기호가 보이지 않지만, 저장 결과는 항상 표준 Markdown이며 다른 도구에서 그대로 열린다.
- **툴바는 두 층**: 자주 쓰는 12개 버튼은 항상 노출, 나머지는 `⋯` 오버플로 메뉴. 툴바 숨김(`Ctrl+Shift+T`)으로 메모장처럼 미니멀하게 사용 가능.
- **컨텍스트 툴바**: 표 안에 커서가 있으면 표 조작 버튼, 코드블록 안이면 언어 선택이 해당 블록 상단에 떠오른다.
- **Fluent Design 준수**: WinUI 3 기본 컨트롤, Mica 배경, 시스템 액센트 색상, 다크 모드.
- **키보드 우선**: 모든 툴바 동작에 단축키 존재. 툴바 없이도 100% 작업 가능.

### 4.3 접근성
- 툴바 버튼 전부 툴팁 + 접근성 이름, 키보드 포커스 이동
- 고대비 테마 대응
- 최소 폰트 크기 12pt, 확대/축소 `Ctrl+=`/`Ctrl+-` (50%~200%)

### 5.3 Round-trip 보존 전략 (핵심 리스크 대응)
WYSIWYG 엔진은 문서를 AST로 파싱 후 재직렬화하므로, 편집하지 않은 영역도 스타일이 바뀔 수 있다(`*` → `_`, 표 정렬 공백, 줄바꿈 등). 이를 막기 위해:
1. 파일 열기 시 원본 텍스트를 블록 단위(문단·표·코드블록 등)로 분할해 각 블록에 원본 문자열을 매핑한다.
2. 편집 엔진에서 "변경된 블록" 이벤트만 추적한다.
3. 저장 시 변경된 블록만 엔진의 직렬화 결과로 교체하고, 나머지는 원본 문자열을 그대로 쓴다.
4. 파일 끝 개행, BOM, CRLF/LF는 원본 값을 보존한다.
5. 측정: 테스트 코퍼스(GitHub README 100개 + 본인 md 50개)를 열고 아무 편집 없이 저장했을 때 diff가 0이어야 한다. (G4)

### 5.4 성능 목표
| 항목 | 목표 |
|---|---|
| 콜드 스타트 → 빈 문서 편집 가능 | ≤ 1.5초 |
| 100KB md 열기 → 렌더 완료 | ≤ 1초 |
| 1MB md 열기 | ≤ 4초, UI 프리징 없음 (프로그레스 표시) |
| 타이핑 지연 | ≤ 50ms |
| 유휴 메모리 (탭 1개) | ≤ 150MB (WebView2 프로세스 포함) |
| 설치 용량 | ≤ 60MB |

### 5.5 안정성·데이터 보호
- 저장은 임시 파일에 쓴 뒤 원자적 교체 (`File.Replace`) — 저장 중 크래시로 파일이 손상되지 않아야 함
- 비정상 종료 시 미저장 내용을 `%LOCALAPPDATA%\MarkPad\recovery\`에 5초 간격 스냅샷, 다음 실행 시 복구 제안
- WebView2 프로세스 크래시 시 에디터 재초기화 + 마지막 스냅샷 복원
- 원격 리소스 로드는 이미지에 한정, 스크립트 실행 차단 (WebView2 설정으로 외부 내비게이션 금지)

| 삽입 | 각주 | 삽입 | `[^1]` | — | 오버플로 |
| 삽입 | 날짜/시간 | 현재 시각 삽입 (메모장 F5 계승) | `2026-09-04 14:30` | `F5` | 오버플로 |
| 편집 | 서식 지우기 | 선택 영역의 인라인 서식 제거 | 평문 | `Ctrl+\` | 오버플로 |

**표 컨텍스트 툴바** (커서가 표 안일 때): 위/아래 행 추가, 좌/우 열 추가, 행 삭제, 열 삭제, 열 정렬(좌/중/우), 표 삭제, 헤더 행 토글.

**코드블록 컨텍스트 툴바**: 언어 드롭다운(검색 가능), 복사, 줄 번호 토글, 블록 삭제.

## 부록 C. 지원 Markdown 규격
- 기준: CommonMark 0.31 + GitHub Flavored Markdown (표, 취소선, 체크리스트, 자동 링크, 각주)
- 확장(설정으로 on/off): 하이라이트 `==` (기본 OFF), 수식 `$` (기본 ON), Mermaid 코드블록 (기본 ON), YAML front matter (기본 ON)
- 원칙: GFM에 없는 확장은 GitHub·VS Code 미리보기와 결과가 달라지므로 기본 OFF. 수식·Mermaid는 GitHub도 렌더하므로 기본 ON
- 인라인 HTML: 렌더는 하되 편집은 소스 블록으로만 (WYSIWYG 조작 대상 아님)
