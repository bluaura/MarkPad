| 설치 용량 | ≤ 60MB | MSIX 29.9MB | ✅ |

## 메모리 분석

- 시작 화면만 열린 상태(WebView2 없음)는 프라이빗 105MB로, 대부분 WinUI/.NET 런타임 자체입니다. WebView2를 만들면 브라우저·GPU·유틸리티·렌더러 프로세스 6개가 추가됩니다(빈 문서 기준 약 +160MB, M0 측정).
- 문서 크기에 비례해 렌더러 메모리가 급증합니다(100KB → 419MB, 1MB → 1,259MB). 원인은 ProseMirror 문서 자체가 아니라 **코드블록마다 생성되는 CodeMirror 인스턴스**와 KaTeX/이미지 NodeView입니다. 코퍼스 README 1MB에는 코드블록이 수백 개 들어 있습니다.
- 따라서 150MB 목표는 WebView2 구조에서 달성할 수 없으며, PRD R3의 재협의 대상입니다. 제안: **"빈 문서 프라이빗 ≤ 300MB, 100KB 일반 문서 ≤ 450MB"**로 재정의하고 아래 절감 항목을 M3에서 수행.

## 절감 후보 (M3)

1. 뷰포트 밖 코드블록은 CodeMirror 대신 정적 하이라이트(Lezer `highlightCode`)로 렌더하고, 포커스 시에만 CodeMirror로 승격 — 1MB 문서 메모리 절반 이하 예상.
2. KaTeX/Mermaid 지연 로드(현재 KaTeX는 메인 번들).
3. WebView2 `AdditionalBrowserArguments`로 유틸리티 프로세스 축소 실험(`--in-process-gpu`, `--disable-features=...`) — 안정성 검증 필요.
4. 시작 화면 단계의 105MB는 WinUI 고정 비용으로 간주.
